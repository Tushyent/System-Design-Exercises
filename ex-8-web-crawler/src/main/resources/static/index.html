Step 2: Live Crawl Controller & Multi-Threaded Worker Matrix Redis List FIFO · Concurrent Workers
Monitor real-time execution across concurrent worker threads (CrawlerWorker-1 … CrawlerWorker-4). Each worker thread dequeues tasks from the frontier queue (RPUSH/LPOP), performs robots.txt verification, checks atomic visited status (SADD), parses DOM trees via Jsoup, validates near-duplicate SHA-256 checksums, and enqueues newly discovered hyperlinks.
Default Configuration: Max Depth: 7 • Max Pages Limit: 50 • Workers: 4 • Politeness: 50 ms. Thread Safety: Atomic integers and Redis sets prevent race conditions across concurrent workers.

Step 4: Discovered Link Topology & Google PageRank Authority Graph Power Iteration (d=0.85)
The discovered web is modeled as a directed graph $G=(V, E)$. PageRank calculates the probability that a random surfer lands on any page. Pages with the most inbound links from authoritative nodes receive the highest score.
Visualization: Blue node = Seed URL; Green = 200 OK; Red = Blocked admin; Purple = Clone. Leaderboard: The root portal achieves score 100.0 due to high inbound edge concentration.

Step 5: Full-Text Search & Relevance Ranking Inverted Index + Okapi BM25
Crawled body text is indexed into an in-memory Inverted Index with a Trie Prefix Autocomplete. Search queries are ranked using Okapi BM25 combined with Google PageRank: Score = 0.6 × BM25 + 0.4 × PageRank.
Demonstration Point: Type words like "quantum", "neural", "sports", "cricket" to test autocomplete suggestions and highlighted snippets.
